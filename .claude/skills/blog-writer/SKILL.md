# blog-writer — 키워드 → 초안 → 발행 직전

사용자는 비개발자다. 한국어로 짧고 쉽게 답한다. 사용자를 '원장님' 같은 호칭으로 부르지 않는다.
글 구조와 발행 기준은 같은 저장소의 `fire-your-seo-agency` 스킬(특히 `references/content.md`,
`references/neo-naver.md`)을 따른다. 이 문서는 그걸 블로그 광고수익용으로 줄인 운영 절차다.

## 불변 규칙

1. **네이버는 자동 발행하지 않는다.** 브라우저 자동 입력·자동 로그인·임시저장 매크로도 만들지 않는다
   (매크로 제재 → 본인 명의 계정 전부 위험). 네이버는 사람이 붙여넣고 발행한다.
2. **사실은 공식 원문으로 확인한다.** 날짜·금액·방법·마감은 공식 출처 2곳 이상. 확인 못 하면 본문에
   "(확인 필요)"를 남기고 사용자에게 말한다. 지어낸 후기·경험담·전문가 인용 금지.
3. **같은 글을 여러 계정·블로그에 올리지 않는다.** 네이버 3계정은 주제를 나눈다:
   ① 방송·연예 ② 정책·생활 ③ 스포츠·행사. 구글 블로거는 같은 주제라도 문장을 새로 쓴다.
4. **쿠팡 파트너스 링크가 있으면** 본문 첫머리나 끝에 대가성 문구를 넣는다:
   "이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다."
5. **사건·사고, 질병 효능, 투자 권유**는 쓰지 않는다 (광고 제한·신뢰 하락).
6. 본업(포장재·박스·보냉재·식품 제조·물류) 관련 주제는 쓰지 않는다.

## 1. 키워드

```bash
python3 issue-keywords/expand.py "<주제>"        # 주제 → 실제 검색어 목록 (네이버·구글 자동완성)
python3 issue-keywords/issues.py --summary       # 지금 뜨는 이슈에서 주제 고르기
```

- **메인 키워드 1개**: 두 곳 모두 나온 "정보" 성격 검색어 중 제일 구체적인 것 (예: "청년도약계좌 신청 조건")
- **보조 키워드 3~5개**: 소제목(H2)이 될 하위 질문
- 구매 성격(가격·추천·후기)이 강하면 쿠팡 링크 글, 정보 성격이면 광고(애드포스트·애드센스) 글
- 어느 네이버 계정(①②③)에 맞는지, 구글 블로거에도 낼지 정한다

## 2. 브리프 5줄 (쓰기 전에 사용자에게 보여준다)

질문(메인 키워드 그대로) / 직답(40자 안팎) / 근거(공식 출처 링크) / 하위 질문(보조 키워드) / 기준일

## 3. 본문 구조

1. **제목**: 메인 키워드를 맨 앞에 + 날짜나 숫자 (예: "청년도약계좌 신청 조건 총정리 (2026년 10월 기준)")
2. **첫 문단 = 직답**: 결론 먼저, 40자 안팎. 네이버 AI 브리핑·구글 AI 요약이 여기를 인용한다
3. **요약 표**: "항목 | 내용" (대상·기간·방법·금액·마감 등). 산문보다 라벨-값 구조가 인용된다
4. **소제목(H2) 3~5개**: 보조 키워드를 그대로 소제목에. 각 소제목 첫 줄도 직답
5. **기준일·출처**: "○월 ○일 기준" + 공식 원문 링크
6. **자주 묻는 질문 2~3개**: 짧은 문답
7. 분량 1,500~2,500자. 같은 문장·키워드 반복 금지 (키워드 억지로 넣기 금지)
8. 사진 자리 표시: `[사진: 공식 공지 캡처]` — 사람이 직접 찍거나 캡처한 사진 1장 이상 권장

## 4. 발행 전 체크 (전부 통과해야 넘긴다)

- [ ] 메인 키워드가 제목 앞·첫 문단·소제목 하나에 있다
- [ ] 첫 문단이 질문에 바로 답한다
- [ ] 모든 날짜·금액이 공식 출처와 일치한다 (확인 못 한 건 "(확인 필요)")
- [ ] 기준일과 출처 링크가 본문에 보인다
- [ ] 쿠팡 링크가 있으면 대가성 문구가 있다
- [ ] 다른 계정·블로그에 같은 글이 없다

## 5. 결과물

`blog-posts/<YYYY-MM-DD>-<짧은-영문-슬러그>/` 폴더에 저장하고 커밋한다 (글 목록이 곧 콘텐츠 장부):

- `naver.html` — 네이버 에디터에 붙여넣을 본문. `<h2> <p> <b> <table> <a> <ul>`만 쓰고 인라인 스타일은
  최소로 (네이버가 대부분 지운다). 제목은 넣지 않는다 (네이버는 제목 칸이 따로 있다)
- `blogger.html` — 블로거 [HTML 보기]용 본문. 맨 끝에 FAQ 구조화 데이터
  (`<script type="application/ld+json">` FAQPage) 포함. 화면의 FAQ와 내용이 정확히 같아야 한다
- `meta.json` — `{title, main_keyword, sub_keywords, naver_account, sources, data_asof, coupang}`

전달:
- 네이버: `naver.html`을 [본문 복사] 버튼이 있는 비공개 Artifact 페이지로 올려 링크를 준다
  (Artifact 규칙대로 `artifact-design` 스킬을 먼저 읽는다). 사용자는 휴대폰에서 복사 → 네이버 앱 붙여넣기
  → 사진 1장·내 한 줄 추가 → 발행
- 구글 블로거: `BLOGGER_BLOG_ID`와 인증이 환경에 있으면 임시저장(draft)으로 올린다.
  아직 연동 전이면 `blogger.html`을 블로거 글쓰기 [HTML 보기]에 붙여넣으라고 안내한다

## 6. 발행 후

- 14일 뒤 네이버 서치어드바이저·구글 서치콘솔에서 노출·클릭 확인 (`fire-your-seo-agency/references/measure.md`)
- 노출이 없으면 제목·첫 문단을 고치고, 같은 질문의 중복 글은 새로 쓰지 말고 기존 글을 갱신한다
